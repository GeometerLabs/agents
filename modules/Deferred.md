What is not done, and why. Each item says what it would take.

| What | Why it waits | What it would take |

| **Modules are not versioned on their own.** A template is pinned (`bookings@0.1.0`), the modules it imports are whatever the app or the server holds. | One template and one version so far, and `geometer update` moves templates, not code beside them. | `pathway.lock` lists modules with a pin (the plan already says "plus any modules, each pinned"). `bundle/lib/pathways.ts` then looks for the right modules folder, and `update.ts` hand-checks a client at both module versions. **The UPI obligation function**, for the unfinished-work inbox (B31). Both are merged now, and the kinds are registered (`unfinished/builtin.ts`); this is their shape.

```ts
// modules/payments/owner-marked/obligations.ts
export function upiObligations(entries: readonly RecordEntry[]): UpiObligation[];
export interface UpiObligation {
  kind: "upi_payment_unconfirmed" | "upi_refund_owed";
  case: string;        // the booking or fee ("b-3", "f-3")
  customer: string;    // the record's conversation (the customer's number); the registry's facts leave it out
  amountPaise: number; // still to be confirmed, or owed back
  since: string;       // ISO time of the entry that opened it (the claim, the part mark, the refund owed)
  id: string;          // the request or refund in the shop's store ("upi-3", "upr-5")
  title: string;       // "UPI payment not yet confirmed by the owner" / "Refund owed by the owner, not yet marked done"
}
export const UPI_OBLIGATION_KINDS: readonly ObligationKind[]; // the two, as registry kinds: facts { case, amountInr, ref }, actions ["ask_owner_again"]
```
