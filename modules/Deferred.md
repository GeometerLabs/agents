# Deferred: shared modules

What is not done, and why. Each item says what it would take.

| What | Why it waits | What it would take |
| --- | --- | --- |
| **Modules are not versioned on their own.** A pathway is pinned (`bookings@0.1.0`), the modules it imports are whatever the app or the server holds. | One template and one version so far, and `geometer update` moves pathways, not code beside them. | `pathway.lock` lists modules with a pin (the plan already says "plus any modules, each pinned"). `bundle/lib/pathways.ts` then looks for the right modules folder, and `update.ts` hand-checks a client at both module versions. Until then the server keeps one `modules/` beside its `pathways/`, and a module change is a change to every template. |
| **The server runtime is still Bookings'.** `server/` (runtime, store, tasks, events, snapshot, ticker) and `inbox/` import the Bookings agent. | Moving them means making the store and the status generic over the template's case (booking, fee). That is its own piece of work and the bundle's compose and panel read their shapes. | Take the case type and the status counts as parameters; then `geometer shop add` can run Fees live. See `pathways/fees/Deferred.md`. |
| **The HTTP Guard stand-in checks refunds only.** `modules/standins/guard.ts` decides holds and refusals for the refund route. The in-process model (`payments/guard-model.ts`) also bounds the amount of a link. | The stand-in is used by `npm run stack` and a few tests, which only ask for refunds. | Call `decideLink` on `POST /v1/payment_links` and answer 403 with the rule's id, as the real Guard does. |
| **The Guard model does not count the caps** (`links-per-hour`, `refunds-per-day`, `refund-paise-per-day`). It reads the spec's bounds and its approval threshold. | The real Guard counts them, and `approvals-guard-binary.test.ts` checks the real binary when it is installed. | Count calls per window in the model, from the spec's `limits`. |
| **Some word lists hold Bookings words.** `language/words.ts` has `book`, `cancel` and `reschedule` beside the shared lists (yes, no, STOP, dates). | Moving them is a rename with no gain until a third template adds its own. | Split the file by template when the third arrives. |
| **Most tests of module code are still in `pathways/bookings/test/`.** Only the ones that needed nothing of Bookings moved (`dates`, `record`), with new tests for the new code. | The rest drive the module through the Bookings agent, which is how it is used; moving them needs the Bookings harness. | Add module-level tests for `payments/refunds.ts` and `messaging/say.ts` with a toy template, as the Fees tests do through the Fees agent. |
| **No type check.** Types are comments here, as in the rest of the repository (Node strips them). A `Reading` or a `RelayVoice` that does not fit is found by a test, not by a compiler. | The repository has no TypeScript compiler, on purpose (no dependencies). | Run `tsc --noEmit` from a pinned install in CI, outside the repository's dependency-free rule. |
| **`understanding/model.ts` shows the cost field names for Bookings.** The record fields the cost meter reads are listed in `pathways/bookings/Explanation.md`. | The meter reads them from the record whatever the template. | Move that table into this folder when a third reader of it appears. |
